# AMD 赛题执行计划与分工

> 本文只讲「**在哪里做、做什么、产出什么、为什么做**」。
> 需要立刻动手写代码的部分放在 `tools/` 与 `src/`，本文只指路、不贴代码。
> 完整题面口径见 [README.md](README.md)。

---

## 0. 目标与分数构成

| 项 | 内容 | 目的 |
| --- | --- | --- |
| 总目标 | 在冻结基线上把 `CREATE VECTOR INDEX ... lib=cuvs` 的端到端构建时间压到 **1/3**，查询吞吐提到 **1.5x** | 满分 20 = 硬门槛 4 + 构建 14 + 查询 2 |
| 构建分 | 14 分，`clamp(ln(加速比)/ln(3.0),0,1)` | **主战场**，3.0x 才满分 |
| 查询分 | 2 分，`clamp(ln(加速比)/ln(1.5),0,1)` | 次要，1.5x 才满分 |
| 硬门槛 | GPU 真建图、Recall、QPS ≥ 基线 90%、显存 ≤ 基线 1.25x、`lib=vsag` 仍可用 | **任一失败 = 0 分**，比性能更重要 |
| 红线 | 不得复用旧图/缓存、不得 CPU 回退冒充 GPU、不得降低 Recall 换速度、不得改评测 SQL 与索引参数 | 违规直接判无效 |

**一句话**：先保证「不判 0」，再压构建时间，最后再抠查询分。

## 1. 角色与机器（人在哪台机器上干活）

| 代号 | 位置 | 能干的事 | 不能干的事 |
| --- | --- | --- | --- |

## 2. 代码地图（改哪里、各自负责什么）

| 位置（都在 `tangtang-cx/seekdb`） | 作用 | 我们要不要动 | 动了的目的 |
| --- | --- | --- | --- |
| `tools/hipvs_bridge/seekdb_cuvs_bridge.c` | **GPU 建图 / 查询 / 快照的唯一入口**，CAGRA 参数、host→GPU 搬运、每次查询的显存申请都在这里 | **主战场，要改** | 降建图成本、去掉每查询固定开销 |
| `tools/hipvs_bridge/build.sh` | 用 `hipcc` 把 bridge 编成 `.so` | 可改，但**官方编译命令必须仍能跑通** | 加编译优化项（如 `-O3`、目标架构） |
| `tools/hipvs_bridge/seekdb_cuvs_bridge.h` | bridge 对内核暴露的接口声明 | 随实现同步 | 接口变化时同步 |
| `src/observer/seekdb/**` | seekdb 内核：建索引 DDL 执行、向量查询 SQL 落地、快照落盘 | **尽量不动**，必要时才动 | 只在「内核侧有重复工作」时才动 |
| `deps/3rd/**`、Rust vendor 目录 | 冻结的第三方依赖 | **禁止新增联网依赖** | 评测编译不联网 |
| `tools/bench_cagra.sh`（新建） | 本地测量脚本：导入 → 建索引 → 首查 → nq=4096 查询 → 落盘指标 | 新增 | 让每轮结果可复现、可比较 |
| `docs/AMD_PERF_REPORT.md`（新建） | CPU/GPU 构建与查询对比报告 | 新增 | 提交材料之一 |

> 原则：**能只在 bridge 里解决，就不动内核**。内核一改，回归面立刻变大。

## 3. 阶段计划（主表）

| 阶段 | 在哪做 | 做什么 | 产出 | 目的 | 完成判定 |
| --- | --- | --- | --- | --- | --- |
| **P0 环境与仓库** | BOX + GIT | ①BOX 装/校验 ROCm 7.2.4、hipVS、编译链；②BOX 打通出网，验证能拉 SIFT1M；③GIT 建 `tangtang-cx/seekdb` 私有 fork 并建只读令牌；④DEV 确认基线 commit 是冻结 commit 的后代 | 环境检查输出、仓库地址与令牌、基线 commit 记录 | 不达标后面全白做，所以放最前面 | BOX 上 4 条验证命令全过；仓库能克隆 |
| **P1 基线复现** | BOX | ①用官方命令编译 bridge 与 seekdb；②造两个数据集：250K×128（SIFT1M 前 250K）、250K×256（SIFT 随机投影代理集）；③写 `bench_cagra.sh`，按官方口径计时；④同轮跑基线 3 轮取中位数 | 基线性能表（两数据集 × 构建时间/首查时间/Recall/QPS/显存峰值） | 没有自己的基线就无法证明「加速比」，也无法验证 Recall 是否掉出 0.005 | 基线构建时间接近官方参考（SIFT 20~27s、Hidden 29~35s 量级），Recall 接近官方（1.000 / 0.985 / 0.914） |
| **P2 参数扫描** | BOX（DEV 改 bridge → BOX 编译测量） | 围绕 CAGRA 建图参数做网格扫描：`graph_degree`、`intermediate_graph_degree`、`nn_descent_niter`、`build_algo`；每个组合在两个数据集上各跑 1 轮，记录构建时间与 Recall | 参数扫描表 + 帕累托前沿图（横轴构建时间、纵轴 Recall） | 用最小改动拿到第一波加速；用数据而不是直觉选参数 | 存在一组参数：构建时间 ≤ 基线 1/3，且两个数据集 Recall 均 ≥ 基线 − 0.005 |
| **P3 搬运与显存** | BOX | 把建图输入从「CPU host 内存交给库自己搬」改成「先 pinned + 异步搬到显存，bridge 直接拿 GPU 张量」；同时给显存申请设上限 | 新版本 + 搬运/显存对比数据 | 建图前的数据搬运是纯浪费；显存峰值还要压在基线 1.25x 内 | 构建时间不劣化、显存峰值 ≤ 基线 1.25x |
| **P4 自定义 GPU 建图** | DEV 写 + BOX 跑 | 官方明确允许在答题仓库里自写 GPU 建图。方向优先级：①并行 NN-descent 自实现；②GPU 粗量化分桶（IVF 式）后桶内建小图再拼装；③两阶段：先用低精度算候选边，再用 FP32 精算 | 自定义建图版本 + 与基线的 Recall/耗时对比 | 参数量到头后，想再快只能自己写图；这一步决定能否上 3x | 自定义版本 Recall 仍 ≥ 基线 − 0.005，构建时间进入满分区间 |
| **P5 查询优化** | DEV 写 + BOX 跑 | 去掉每次查询的显存申请/释放与逐次拷贝；改持久化 device buffer + pinned staging + 预取；确认并消除「每查询重载快照」；`search_width`/`itopk_size` 只在 Recall 允许范围内调 | 查询优化版本 + nq=4096 的 QPS/P95 对比 | 4096 次单行查询把每次的固定开销放大；这 2 分相对好拿 | 查询吞吐 ≥ 基线 1.5x，且 Recall 不掉 |
| **P6 加固回归** | BOX | 跑齐所有硬门槛自检项；`lib=vsag` CPU 路径回归；连续 3 轮稳定性；显存/内存峰值复核 | 门槛自检表（全部 ✓）、稳定性记录 | 硬门槛是「一票否决」，性能再好也可能 0 分 | 自检表全绿，连续 3 轮不崩 |
| **P7 报告与提测** | DEV + GIT + SUB | 写一页性能报告（基线 vs 候选 × 两数据集 × 多轮中位数 + 方法说明）；把最终代码压成一个分支 + 一个 commit；在提测平台填「仓库地址（带只读令牌）+ 分支 + commit」；准备答辩口径 | 报告、最终 commit、提测记录 | 官方只认「仓库地址 + 分支 + commit」，格式错了直接 `failMsg=4` | 平台克隆成功并给出分数（不是 `failMsg`） |

## 4. 测量口径（所有人必须用同一套，否则数据不可比）

| 项 | 口径 |
| --- | --- |
| 计时起点 | 执行建索引 DDL 之前（表已导入、无索引、无缓存、无旧图） |
| 计时终点 | 索引可查询 **且第一条固定查询完成并返回合法结果** |
| 每轮清理 | 清索引、清缓存、清旧图，重新从导入后的状态开始 |
| 配对方式 | 同轮跑「冻结基线 + 候选」，两个数据集交换先后顺序，降低温度/时钟偏差 |
| 统计口径 | 报中位数（≥3 轮），同时保留原始数据 |
| 数据集 | ①SIFT250K（250K×128，公开对应）②自建 250K×256 代理集（Hidden 的替身） |
| 指标 | 构建时间、首查时间、Recall@10/@100、nq=4096 的 Top-10/Top-100 QPS 与 P95、显存峰值、内存峰值 |
| GPU 真实性 | 每轮构建期间采集 GPU 利用率留证（应对评测的 GPU 路径抽检） |

## 5. 硬门槛自检清单（P6 逐条打勾）

- [ ] 代码可从源码编译成功（官方那两条命令原样可跑）
- [ ] 每条查询返回 k 个**互不重复**的合法 ID
- [ ] SIFT250K Recall@10/@100 ≥ 0.95
- [ ] Hidden250K Recall@10 ≥ 0.90、Recall@100 ≥ 0.85
- [ ] 两个数据集 Recall 相比同轮基线下降均 ≤ 0.005
- [ ] GPU 实质参与建图与查询（可被 profiler 抽检到）
- [ ] 查询吞吐 ≥ 同轮基线 90%（Top-10、Top-100 分别 ≥ 90%）
- [ ] 显存峰值 ≤ 同轮基线 1.25x，内存 ≤ 96GB
- [ ] `lib=vsag` 路径的建表 / 建索引 / 查询仍然可用
- [ ] 连续 3 轮运行无崩溃、无索引损坏

## 7. 风险与预案

| 风险 | 预案 |
| --- | --- |
| 降参后 Recall 掉出 0.005 容忍 | 先在公开 SIFT 上扫前沿；必要时用 P4 自定义建图把精度换回来 |
| 256 维代理集与真 Hidden 行为不一致 | 代理集只用于保守筛选，最终仍以官方分数为准，多留参数余量 |
| 编译不联网、缺冻结依赖 | P0 就把依赖 vendor 进仓库；不新增联网依赖 |
| 显存超 1.25x | 分块构建、显式设显存申请上限、避免同时驻留两份图 |
| 评测机 GPU 与本地不同 | 尽量用 W7900D；参数不要贴着 Recall 下限 |
| 自定义建图与官方 CAGRA 搜索不兼容 | P4 优先做「产出 CAGRA 兼容快照」，走官方反序列化路径 |
| 提测被 `failMsg=4` 拦下 | 仓库地址必须写成 `https://用户名:只读令牌@github.com/所有者/仓库` |

## 8. 红线（违反直接无效）

1. 不用预编译二进制代替源码构建。
2. 不复用上一轮图 / 索引文件 / 缓存来"加速"。
3. 不用 CPU 结果冒充 GPU 建图或查询。
4. 不靠降低 Recall 换性能。
5. 不改评测 SQL、索引参数、输入数据精度与规模。
6. 不修改评测固定的 hipVS/cuVS 库本身。
7. 不针对隐藏数据做特化。
